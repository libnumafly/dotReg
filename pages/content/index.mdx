## A full key. A shared heading. The same setting.

Write each dotted key in full, or group related settings beneath a heading. Values begin as text; your application decides how to interpret them.

<div class="notation-pair">

```text title="Full keys"
@dotReg 1

A.Code:001
A.Message: "Hello, dotReg"
A.Group.Enabled:true
```

```text title="Grouped keys"
@dotReg 1

A.
 .Code:001
 .Message: "Hello, dotReg"
 .Group.
  .Enabled:true
```

</div>

Both forms resolve to `A.Code`, `A.Message` and `A.Group.Enabled`. The code `001` keeps its leading zeroes. Every complete file starts with `@dotReg 1` and a blank separator.

<div class="notation-principles">
  <section>
    <h3>Text stays text</h3>
    <p>Keep paths, codes and literal values intact. Use an initial double quote when you want quoted syntax and escapes.</p>
  </section>
  <section>
    <h3>Every occurrence counts</h3>
    <p>Repeat a key to record multiple values in source order. Repeated values are retained, including identical ones.</p>
  </section>
  <section>
    <h3>Room for longer values</h3>
    <p>Use triple quotes for decoded multiline strings, or pipe blocks for literal text.</p>
  </section>
</div>
